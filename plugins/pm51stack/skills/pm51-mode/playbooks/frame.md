# Frame

A decision is still open. Production code waits until the decision is explicit.

1. Restate the decision, who it is for, and what would count as settled.
2. When the user is stress-testing a plan, read `grilling` and follow it. One question at a time.
3. When the fight is a term, the glossary, or an ADR, read `domain-modeling` and follow it, after grilling if the plan is also unsettled.
4. When the missing piece is a fact outside this working tree, read `research` and follow it.
5. When a throwaway sketch of logic, state, or UI would settle the question, read `prototype` and follow it. Build the sketch. Ask the user only what the sketch cannot show.
6. Stop when the decisions are written down in the conversation. The next playbook is specify when the user wants that recorded, or feature when they want the settled slice built.

Reply with the decisions, the options you closed, and the one that remains if any.
